# ERD Maker

Draw entity–relationship diagrams in the browser: Chen notation or crow’s-foot tables, keys and relationships included. Share a live room or download a diagram. No account.

Diagrams save in your browser. Download a JSON backup (Ctrl+S) before clearing browser data.

## Get started

1. **Draw** — use **Add your first entity**, or open an example: Customer–Order, Student–Course, Employee–Dependent. Each opens in its own room.
2. **Name** — new shapes take typing immediately. Double-click later to edit.
3. **Share or download** — a room link, or SVG, PNG, JSON, or SQL.

<details>
<summary><strong>⚙️ For developers: run locally</strong></summary>

```bash
npm install
npm run dev
npm run verify
```

Verification runs unit tests, TypeScript, a production build, and browser tests. Browser tests start Vite preview and a local y-webrtc signaling server, with no public dependency. Rooms save through IndexedDB.

</details>

## Build a diagram

- **Build panel** adds entities, attributes, relationships, specializations.
- **Connect** in Chen: drag entity to entity. It creates the diamond with both participants. Drag onto a diamond to add a participant.
- **Connect** in crow’s-foot: pick two attribute rows. Change an endpoint via **Connection attribute**; **Automatic** follows the inferred key and foreign key.
- **Check diagram** flags missing names and keys, stray attributes, incomplete relationships, and invalid ranges. A hint opens the affected properties.
- **Fit** frames the drawing. **Add unary relationship** in Properties links an entity to itself.
- Entities come as Regular, Weak, or Associative.
- A crow’s-foot row with no attribute behind it was generated by the diagram. It stays editable and takes your name.

<details>
<summary><strong>⚙️ For developers: exact-schema details</strong></summary>

- **Unique** is a candidate key: it identifies a row but is not the primary key, and another table may reference it instead. Marked `UQ` in tables, broken underline in Chen, `UNIQUE` in SQL. **Key** instead makes it part of the primary key, and a foreign key must then carry every part. A generated primary-key role leaves an existing `id` editable.
- **Composite attributes** own parts via **Add attribute** or **Belongs to**. Chen draws the hierarchy; tables and SQL use leaf names like `billing_address_street`, keeping each leaf’s key and type. No parts means a scalar column. Deleting one removes its subtree; Undo restores it.
- **Hand-shaped lines** use dbdiagram-style controls: round handle or section drags perpendicular, square splits at midpoint, Enter adds a section, arrows nudge (Shift larger), Escape cancels, **Route line automatically** restores routing. Neighbouring sections snap together; self-intersections are blocked, endpoint stubs protected. Segment positions sync live and survive reloads.
- **Table positions** sync separately from Chen positions; auto-arrange never overrules a hand move, and the newest placement wins a conflict.
- Specializations and attributes on relationships live in **Diagram**; selecting one switches to Chen.

</details>

## Move around

- Scroll zooms toward the pointer; trackpad and two-finger pinch zoom too. Range: 25% to 300%.
- Left controls: Build, Diagram, Properties, Help. On phones they move to the bottom bar.
- **Focus view** (I) hides controls; Escape or I returns.
- Right-click canvas or a shape for its menu. Shift-click multi-selects. Shift-drag box-selects.
- Undo and Redo apply to edits; remote changes stay shared.

<details>
<summary><strong>⚙️ For developers: phone and menu specifics</strong></summary>

Editing sheets take at most 45% of the screen, keep normal scrolling, and stay above the on-screen keyboard; **Done** returns to the drawing while Select, Connect, Pan, Undo, and Redo stay reachable. Right-click menus also open with **Shift+F10** or the **Menu key**: arrows navigate, Enter activates, Escape or Tab closes. Right-clicking a selected shape keeps the selection.

</details>

## Notation

| Chen symbol | Meaning |
| --- | --- |
| Rectangle | Entity |
| Ellipse | Attribute |
| Diamond | Relationship |
| Triangle | Specialization |
| Double rectangle | Weak entity |
| Double diamond | Identifying relationship |
| Double ellipse | Multivalued attribute |
| Dashed ellipse | Derived attribute |
| Underlined attribute | Key |

A weak entity’s partial key identifies it within its parent; SQL combines it with the parent’s key.

<details>
<summary><strong>⚙️ For developers: endpoint symbols and ranges</strong></summary>

Chen endpoints follow ERDPlus: two bars required one, circle and bar optional one, bar and fork required many, circle and fork optional many. N and M both use the fork. Click an endpoint to edit constraints; advanced numeric ranges stay visible beside the line. **Minimum / maximum** takes whole numbers and N; invalid input stays local until corrected, and relationships may stay incomplete or exceed two participants.

</details>

Each person picks their own notation, stored per room and browser. JSON files and snapshots keep the exporter’s view field and current notation.

## Rooms and sharing

- New diagrams open in new rooms. Browser Back returns with the work saved.
- **Share** gives a short room link. The room is kept on the sync server, so the link opens the diagram even when nobody else is online; while it loads you may see **Waiting for the diagram** and the room code.
- **Include diagram snapshot** puts the diagram in the link itself: longer, and it opens with no server at all. It starts ticked when the app has no sync server to keep rooms. Both link types allow editing.
- **Save a copy** writes JSON that needs no server and survives chat apps. **Import** replaces the room you are in; Undo brings the old diagram back, and an invalid file leaves the room intact.
- **Your name** is asked on an empty diagram, stored per browser, and sent to peers as you type.
- A diagram lives in its room, in this browser, and — when a sync server is set up — on that server, so a link still opens later.

The header names the connection state:

| Status | Meaning |
| --- | --- |
| **Live** | Edits flow between browsers |
| **Same browser** | Other people are in this browser only |
| **Waiting** | The room is reachable, nobody else is in it |
| **Offline** | The signaling server is unreachable |
| **Blocked** | A peer was found; the network refused the connection |

A peer’s cursor appears only in the same notation, since the two views place one schema at different coordinates. Closing a tab removes a cursor immediately.

<details>
<summary><strong>⚙️ For developers: how connections work</strong></summary>

Tabs in one browser sync over BroadcastChannel; separate browsers use a sync server when one is configured, and WebRTC with a signaling server otherwise. Presence comes from connected peers and is shown apart from browser storage. **Offline** and **Blocked** offer **Share**, where a snapshot link can be copied.

With `VITE_SYNC_URL` set, the app talks to Cloudflare's `cloudflare/worker.js` instead of the signaling servers; that worker writes a room to storage when the last person leaves, which is what lets a short link open with nobody online. Without it, default server: `wss://signaling.fly.dev`. Override with `?signaling=`, `window.__ERD_SIGNALING__`, or `VITE_SIGNALING`. If direct connections are blocked, editing and snapshot links still work; cross-device live edits do not arrive.

</details>

## Export

SVG, PNG, JSON, SQL. Image exports use the full drawing bounds and strip selection, hover, connection, and presence overlays.

<details>
<summary><strong>⚙️ For developers: SQL export rules</strong></summary>

The SQL tab offers a dialect: Standard SQL, PostgreSQL, MySQL, or SQLite. It changes only generated key spelling (`INTEGER`, `SERIAL`, `INT AUTO_INCREMENT`), stored per browser and exporter, not per diagram.

Mapping: entities become tables, weak entities borrow the parent key, many-to-many makes junction tables, one-to-many adds foreign keys. Connection attributes supply the actual columns; explicit one-to-one enforces uniqueness. The export explains a reference that needs a single-column primary key or an endpoint that is gone. Foreign-key types follow the referenced key; other types use the chosen type or infer from the name.

Types are a base plus numbers: length for `VARCHAR`, precision and scale for `DECIMAL`, so `VARCHAR(64)` and `NUMERIC(12,4)` instead of fixed presets. Bases: integers, text, character strings, numeric, boolean, date/time, UUID, JSON, bytea, enum. `ENUM` takes a comma-separated list, shown as SQL (`ENUM('pending','active','closed')`); quotes are optional on input, added on export, and escaped. Bad numbers such as `VARCHAR(0)` are refused, not repaired. Types persist through edits, collaboration, JSON, and snapshots. SQL/DBML import is out of scope.

</details>

## AI authoring (MCP)

An AI assistant can open, build, and edit diagrams through the MCP server in `mcp/`. It works on the same JSON the app imports, so its output opens here, and its validation, SQL, and share links come from the app's own code. It can also join a live room as a collaborator: its edits then appear in every open tab as it makes them, with its name, cursor, and selection, so there is nothing to refresh.

Placement is the assistant's job, not a side effect. `create_diagram` accepts an `x` and `y` for each entity, `summarize_diagram` reports where every entity sits, and `update_node` moves one, carrying its attributes in Chen notation. Anything left without coordinates takes the next free slot beside its neighbours. Automatic arrangement is opt-in through `layout: true` or `arrange_diagram`, so a diagram drawn with positions opens exactly as drawn.

<details>
<summary><strong>⚙️ For developers: MCP setup</strong></summary>

Install once with `npm install`, then run `npm run mcp` to check that the server starts. It speaks MCP over stdio, so the client launches it; there is no build step.

To connect a client:

- **Project MCP file.** `.mcp.json` in this folder already points at `mcp/start.mjs`. Clients that read a project MCP file, Claude Code among them, connect when the folder is open.
- **Custom server entry.** In a client with its own server list, add a stdio server named `erd-maker` with command `node` and one argument, the absolute path to `mcp/start.mjs`. In Qoder Desktop, open Settings > Extensions > Connectors, choose Add Connector, then Add custom MCP.
- **Manual config.** Any client that edits MCP JSON takes this entry:

```json
{
  "mcpServers": {
    "erd-maker": {
      "command": "node",
      "args": ["C:/path/to/erd-maker/mcp/start.mjs"]
    }
  }
}
```

Restart the client or reconnect the server after adding the entry. To confirm the connection, ask the assistant to create a diagram for customers and orders and return the share link, or check that the tool list contains `create_diagram`.

### Live rooms

Open a diagram in the app, copy the address-bar link, and ask the assistant to call `open_room` with it. The app already syncs through its relay, so the MCP joins the same room as an ordinary client:

- Every later add/update/remove call appears in the open tab immediately, with the assistant's cursor on the shape it changed. No refresh, no re-import. The cursor slides between shapes along a curved, eased path published at screen frame rate, so the work reads as a hand moving rather than shapes teleporting.
- The assistant is a peer like anyone else: it shows up in the presence strip and on the canvas with the name and colour from `ERD_MCP_AI_NAME` and `ERD_MCP_AI_COLOR`.
- `open_room` with no link starts a new room and returns a link that opens it. A room with content already in it is left alone; the open diagram or the link's snapshot only seeds an empty room, so the room always wins.
- `leave_room` signs out when the person says they are done: the pointer glides back to the last shape, pauses with the typing indicator up, then disconnects, so watchers see the assistant finish instead of an avatar that stopped moving. The diagram stays open in the MCP, and `open_room` rejoins with the pointer where it left off.
- Edits are diffs against the current room, so concurrent changes to other shapes survive. `create_diagram` while in a room replaces the room content and streams it in shape by shape.
- AI edits arrive as ordinary remote changes, so they are not local undo steps for the watcher. Both directions keep syncing.

The MCP reaches the hosted app through the same Cloudflare relay the app uses, joining with the app's origin because the relay allowlists browsers. The two relay variables below override that for a relay of your own.

Files stay under the repository root:

| Variable | Default | Purpose |
| --- | --- | --- |
| `ERD_MCP_ROOT` | repository root | Paths outside this directory are refused. |
| `ERD_MCP_DIR` | `diagrams` | Where a new diagram goes when the call omits a path. |
| `ERD_MCP_APP_URL` | `http://localhost:5173/` | Base URL for share links, including a room started by `open_room`. |
| `ERD_MCP_RELAY_URL` | `wss://erd-sync.cerberus-tusk-proxy.workers.dev` | Relay a live room connects to. |
| `ERD_MCP_RELAY_ORIGIN` | `https://kuy124.github.io` | Origin sent to the relay; it must be in `ALLOWED_ORIGINS`. |
| `ERD_MCP_AI_NAME` | `AI assistant` | Name peers see in a live room. |
| `ERD_MCP_AI_COLOR` | `#6B3FA0` | Presence colour peers see. |

Eighteen tools cover the diagram: `create_diagram`, `open_diagram`, `open_room`, `leave_room`, `save_diagram`, `list_diagrams`, `get_diagram`, `summarize_diagram`, `validate_diagram`, `generate_sql`, `arrange_diagram`, `add_entity`, `add_attribute`, `add_relationship`, `update_node`, `remove_node`, `update_diagram`, `create_share_link`. The open diagram is also an MCP resource (`erd://current`, plus `erd://current/summary` and `erd://current/sql`), and a `design-erd` prompt walks a model from requirements to a validated diagram.

Paths must end in `.json` and stay inside the workspace. A call that fails leaves the open diagram unchanged, and saving over an existing file needs `overwrite: true`.

</details>

## Look

IBM Plex type, paper-and-ink surfaces, quiet drafting grids, teal selection. Follows system light or dark and reduced motion. Help adds **Solarized Light**, **Solarized Dark**, **Dracula**, **Nord**, **GitHub Dark**, and **Monokai** using each project’s published values. Themes change colour tokens only, all at 4.5:1 body contrast. The choice is stored per browser; **System** clears it.
